# 나를봄 · Nareulbom

> 나를 알아가고, 나에게 맞게 챙기다.

약·영양제 검색과 건강정보 기반 맞춤 관리를 목표로 하는 iOS·Android 앱입니다.
기술 기반은 housing-tracker-mobile과 같은 Expo 57 / React Native 0.86 / TypeScript / Expo Router / Node.js입니다.
디자인과 서비스 코드는 별도로 구성합니다.

## 현재 구현

- 첫 실행 건강정보 문진 → 홈 / 검색 / 복용함 / 가이드 / 내 정보 5개 탭
- 관리 목표·기본정보·건강 상태·복용 제품·생활습관·영양정보 6단계 입력과 프로필 수정·삭제
- 문진 결과에 따른 홈 목표·이어서 할 일·복용 제품 및 기록한 일정 표시
- 일반약 설명(e약은요) / 전체 의약품(제품 허가정보) 검색·더 보기·상세·출처 표시
- 검색되지 않는 약·영양제 직접 등록·수정, 제품 정보 미확인 표시
- 정확한 제품 확인 후 복용 목록 추가·삭제·상세 다시 보기
- 질병관리청·NIH ODS 공식 자료 링크
- Node.js 검색 API, 입력 검증, 상류 API 오류·빈 결과 구분
- Docker 실행 설정, 서버 회귀 테스트

모바일 기기 보관 동의 후 복용 목록·복용량·매일/필요 시 일정 저장, 개별·전체 삭제를 지원합니다. 웹은 임시 보관입니다.
로그인, 기기 간 동기화, 영양제 공식 데이터·성분 검색, DUR 분석, AI 추천은 아직 구현하지 않았습니다.
실제 개인 건강정보를 입력하거나 보관하는 출시용 서비스가 아닙니다.

## 실행

Node.js 22.13 이상이 필요합니다.

```bash
npm install
cp .env.example .env
npm run server
```

별도 터미널:

```bash
npm start
# 브라우저 미리보기
npm run web
# 네이티브 빌드 (Xcode 또는 Android 개발 환경 필요)
npm run ios
npm run android
```

검색하려면 공공데이터포털에서 e약은요 활용 신청 후 `.env`의 `MFDS_SERVICE_KEY`에 **Decoding 인증키**를 설정하고 서버를 다시 실행합니다.
키가 없을 때는 검색을 준비 중이라는 안내를 표시합니다. 가짜 의약품 결과를 반환하지 않습니다.

`EXPO_PUBLIC_API_URL`은 모바일 앱에서 접근할 서버 주소입니다. iOS 시뮬레이터·웹은 localhost,
Android 에뮬레이터는 10.0.2.2, 실기기는 개발 컴퓨터의 LAN IP를 사용하세요.
환경변수 변경 후 Expo를 다시 시작하세요. 웹 포트 변경 시 CORS_ORIGIN도 맞춰 주세요.

## 실제 검색 연결 확인

1. https://www.data.go.kr/data/15075057/openapi.do 에서 e약은요 활용 신청을 완료한다.
2. 로컬 `.env`의 `MFDS_SERVICE_KEY`에 Decoding 인증키를 입력한다. 채팅·커밋·스크린샷에 키를 포함하지 않는다.
3. `npm run check:api`로 실제 조회를 검증한다. 인증키는 출력하지 않는다.
4. API 서버를 다시 시작한다 (`npm run server`).
5. 앱에서 검색 → 결과 더 보기 → 제품 상세 → 제품명·제조사 확인 → 복용함 추가 → 복용함 상세 다시 보기를 확인한다.

추가 페이지 실패 시 기존 결과를 유지하며 동일 페이지를 재시도한다. 검색어를 수정하고 더 보기를 눌러도 기존 제출 검색어를 사용한다.
e약은요는 일부 일반의약품 정보를 제공하므로 처방약·영양제 전체 검색으로 해석하지 않는다.
성공 결과는 실제 인증키 연결 후 검증해야 한다. 테스트의 제품 데이터는 자동 테스트에만 사용하며 앱 API에 노출하지 않는다.

## 복용함 기기 보관과 일정

- 모바일에서 별도 보관 동의를 받은 뒤 SecureStore를 사용한다. 서버에 복용량·일정을 전송하지 않는다.
- 품목 코드·이름·제조사·설명 출처·수정일과 직접 입력한 복용량·시간만 저장한다. 긴 의약품 설명은 저장하지 않고 품목 코드로 다시 조회한다.
- 보관을 거부해도 검색·임시 목록·일정 기록은 사용 가능하다. 웹에서는 보안 보관을 제공하지 않으며 재실행 시 초기화된다.
- 일정은 1회 복용량(단위 포함 직접 입력), 매일/필요 시, 매일의 경우 HH:MM 형식 최대 8개로 구성한다. 처방량을 자동 제안하지 않는다.
- 현재 매일 반복·필요 시 기록만 지원한다. 요일별·기간별 일정은 미구현이며, 매일 복용 알림은 내 정보에서 선택할 수 있다.
- 내 정보에서 전체 삭제와 동의 철회를 함께 실행할 수 있다. iOS는 앱 삭제 후 Keychain 데이터가 남을 수 있으므로 앱의 전체 삭제를 사용한다.
- 큰 저장값은 UTF-8 1,500바이트 이하 조각으로 나눈다. 이중 슬롯과 단일 커밋 키로 저장 중단 시 이전 상태를 유지한다.
- 삭제 중단 상태를 기록하고, 삭제가 끝나지 않으면 읽기·쓰기를 막아 재시도하게 한다. 저장 오류 시 임의 초기화하지 않는다.

검증: `npm run test:storage` 7개, `npm run test:server` 10개, 타입 검사·웹 빌드·iOS 시뮬레이터 네이티브 빌드 통과.
브라우저의 임시 데이터로 잘못된 시간 차단, 일정 저장·수정·필요 시 전환·일정 삭제, 삭제 취소·전체 삭제를 확인했다.
모바일 실제 강제 종료 후 보관 유지와 Android 기기 QA는 추가 확인이 필요하다.

## 처방약 검색과 직접 등록 (2026-10-21)

- 검색의 `전체 의약품`은 식약처 의약품 제품 허가정보를 조회한다. 전문·일반 구분, 성분, 허가 상태와 효능·용법·주의사항을 표시한다. 허가정보가 현재 판매·공급을 보장하지 않는다.
- [활용 신청](https://www.data.go.kr/data/15095677/openapi.do) 후 기존 `MFDS_SERVICE_KEY`를 사용한다. 별도 키가 필요하면 서버 전용 `MFDS_PERMIT_SERVICE_KEY`를 설정한다. 인증 거부를 검색 결과 없음으로 처리하지 않는다.
- 공식 명세의 `DrugPrdtPrmsnInfoService08/getDrugPrdtPrmsnDtlInq08`을 사용한다. `npm run check:permit`으로 실제 연결을 확인한다.
- `GET /api/drugs?q=제품명&page=1&source=permit`: 허가정보 20개 단위 검색. `source=easy`가 기본이며 두 출처의 검색 결과·페이지는 별도로 관리한다.
- `GET /api/drugs/:id?source=permit`: 품목 코드가 일치하는 제품만 상세 반환한다. 허가 문서 XML은 텍스트로 표시하므로 표·서식은 식약처 원문에서 확인한다.
- 직접 등록은 제품명·함량·제조사·약/영양제 구분을 기록한다. 공식 제품과 자동 연결하지 않으며, 정보 미확인 상태를 유지한다. 효능·금기·상호작용 결과를 생성하지 않는다.
- 직접 등록 제품도 복용량·일정과 함께 보관한다. 제품 정보를 수정해도 일정은 유지하며 동일한 입력의 중복 등록은 차단한다.
- 실제 노바스크 검색 3개와 품목 코드 상세 일치, 사용법·주의사항 응답을 확인했다. 브라우저에서 직접 등록·수정·중복 차단·일정 유지·미확인 상세 표시를 검증했다.
- 서버 테스트 15개, 보관·모델 테스트 10개, 타입 검사 및 웹 빌드 통과. 이번 변경은 네이티브 의존성을 추가하지 않았다.

## 첫 실행 건강정보 입력

- 건강정보 입력·이용 동의는 앱 전체 이용에 대한 선택 동의다. 미체크 상태에서도 `입력 없이 시작하기`로 검색·복용함에 진입하며, 체크하면 버튼이 `동의하고 문진 시작`으로 바뀐다.
- 문진은 관리 목표 → 기본정보(연령대·성별·키·몸무게) → 건강 상태(진단 질환·알레르기·임신·수유) → 복용 약·영양제 → 생활습관 순서다. 모든 문항은 건너뛸 수 있으며, 미입력·모름과 없음은 구분한다.
- 복용 제품은 기존 검색·제품 확인 또는 직접 등록을 사용한다. 문진 완료 전에도 제품 등록은 복용함에 반영된다. 문진 답변은 최종 확인 후 반영하며 수정 중 닫으면 기존 프로필을 유지한다.
- 건강정보 기기 보관 동의는 마지막 화면에서 따로 선택한다. 건강정보 보관 동의로 복용함까지 자동 저장하지 않으며, 복용함 보관 동의로 건강정보를 자동 저장하지 않는다.
- 동의한 정보는 기존 SecureStore 보안 저장소에 보관한다. 문진 답변은 서버·AI·일반 로그로 전송하지 않는다. 동의하지 않은 건강정보와 웹의 모든 입력은 이번 실행에서만 유지된다.
- 모바일은 건강정보 보관 여부와 별도로 안내 완료 여부만 기억한다. 전체 삭제 후 다음 실행에는 안내가 다시 나타난다. 기존 v1 복용함 데이터는 유지하고 v2 저장 형식으로 갱신한다.
- 내 정보에서 프로필 재입력·건강정보만 삭제·전체 삭제와 동의 철회를 제공한다. 맞춤 추천·금기 판정·질환 진단은 아직 제공하지 않는다.
- 검증: 보관·모델 테스트 16개와 서버 테스트 15개, 타입 검사·웹 빌드 통과. 브라우저에서 미동의 앱 진입, 단계 이동·건너뛰기, 숫자 오류 차단, 약 등록 후 문진 유지, 최종 확인·홈 전환·수정 취소를 확인했다. 모바일 재실행 및 Android 실제 기기 확인은 추가 검증이 필요하다.

## 건강 프로필을 반영한 홈

- 선택한 관리 목표를 모두 표시하고, 첫 번째 선택 목표에 따라 프로필·생활습관·복용함·기존 공식 자료 가이드로 연결한다. 개인별 의학적 적합성이나 추천 결과가 아니다.
- 미입력 항목과 복용 일정 미입력 상태에서 이어서 할 일을 최대 2개 표시한다. 누르면 해당 문진 단계 또는 복용함·검색으로 이동한다. 프로필 저장 후 홈에 즉시 반영한다.
- 미입력·모름과 명시적인 없음을 구분한다. 성별·키·몸무게·임신·수유 등 선택 항목을 홈의 필수 과제로 만들지 않는다. 건강 점수를 산출하지 않는다.
- 복용함에는 최대 3개 제품과 사용자가 직접 기록한 매일/필요 시 일정이 표시된다. 직접 등록 제품은 정보 미확인 상태를 유지한다. 표시한 일정은 복용 완료나 실제 알림을 뜻하지 않는다.
- 문진을 건너뛰어도 검색·복용함을 사용할 수 있고, 홈에서 건강정보 입력을 선택할 수 있다. 문진 단계만 이동 인자로 사용하며 건강정보는 URL에 포함하지 않는다.
- 검증: 보관·모델 테스트 21개, 타입 검사와 웹 빌드 통과. 브라우저에서 미동의 홈, 목표 반영, 해당 문진 단계 직접 진입, 수정 후 홈 즉시 갱신, 동일 링크 반복 진입을 확인했다. 기기별 네이티브 QA는 별도 확인이 필요하다.

## 목표·질환별 가이드

- 가이드의 `나의 가이드`는 문진의 선택 목표와 확인된 질환명으로 자료를 연결하고 연결 이유를 표시한다. `전체 자료`에서는 건강정보 입력 없이 공식 자료 6개를 볼 수 있다.
- 수면·휴식/활력 → 수면 습관, 영양제 알아보기 → 영양제 기초·비타민 D, 복용 약 관리 → 영양제와 약을 함께 확인하는 기초 정보, 꾸준한 관리/질환 정보 목표 → 국가건강정보포털로 연결한다.
- 현재 질환 연결 이름은 고혈압, 당뇨병/당뇨다. 공백만 정리하고 정확히 일치할 때 연결하며 증상·제품·알레르기에서 질환을 추정하거나 부분 일치로 연결하지 않는다. 그 외 입력은 연결 자료 없음으로 표시한다.
- NIH 자료 3개는 확인한 원문의 일부를 짧게 한국어로 정리한다. 영문 원문과 국내 기준 차이를 안내하며 개인별 복용량·결핍·치료·안전성을 판정하지 않는다.

- 상세 화면에서 출처, 원문 제목, 원문 갱신일, 앱 자료 확인일을 구분한다. 갱신일이 표시되지 않은 자료에는 임의 날짜를 넣지 않는다. 앱 확인일은 의료 전문가 검토일이 아니다.
- 매칭은 기기에서 수행한다. 외부 원문 링크는 고정된 공개 URL이며 사용자의 건강정보를 쿼리나 로그로 전송하지 않는다.
- 검증: 모델·보관 테스트 26개, 타입 검사·웹 빌드 통과. 브라우저에서 비동의 전체 자료 열람, 상세 출처·날짜, 목표·질환 연결, 미연결 안내와 당뇨병 원문 직접 연결을 확인했다.

## 증상별 일반약 안내: 두통

- 홈의 `증상으로 일반약 알아보기` → `/symptoms`에서 두통 질문·진료 확인 사항·약사 상담용 성분을 안내한다. 첫 범위는 두통과 아세트아미노펜이며 다른 증상·처방약 선택·상품·용량 추천은 미구현이다.
- 이번 증상 답변과 기존 프로필·복용함을 함께 사용하는 선택 동의를 받는다. 미동의 상태에서는 홈으로 돌아갈 수 있고 응급 안내는 읽을 수 있다.

## 오늘의 복용 기록

- 홈에서 기기의 현재 날짜에 해당하는 매일 일정을 시간순으로 표시한다. 필요 시·일정 미입력 제품은 별도로 안내하며 자동으로 미복용/건너뜀을 판단하지 않는다.
- 각 제품·날짜·시간·직접 입력한 1회 복용량별로 `먹었어요` 또는 `건너뛰기`를 기록하고 취소할 수 있다. 기록 시각은 실제 복용 시각을 확정하는 값이 아니다.
- 앱 활성화와 주기적 날짜 갱신으로 자정을 반영하며, 날짜가 지난 화면에서 기록을 누르면 현재 목록을 다시 확인하도록 한다. 기기 현지 날짜를 사용하고 UTC 날짜로 자르지 않는다.
- 일정의 시간·복용량을 바꾸면 변경 전 기록을 별도로 표시한다. 새로운 일정에 과거 완료 상태를 자동 적용하지 않는다. 제품을 삭제하면 해당 제품의 복용 기록도 함께 삭제한다.
- 기존 복용함 보관 동의만으로 기록을 저장하지 않는다. 내 정보에서 별도로 `복용 기록 기기 보관에 동의 (선택)`를 선택한 뒤 SecureStore에 보관하며, 웹과 미동의 상태에서는 실행 중 메모리에서만 유지한다. 기존 v1/v2 저장 형식은 그대로 읽는다.
- 기록은 최근 30일 범위·최대 400개로 제한한다. 오래된 기록은 읽기 시 제외하고 다음 상태 저장에서 저장본도 정리한다. 내 정보에서 기록만 삭제·기록 보관 동의 철회가 가능하고, 전체 삭제는 기록을 포함한다.
- 과거 기록 달력·필요 시 복용의 개별 기록은 후속 단계다. 기록을 서버로 전송하지 않는다.
- 검증: `npm run typecheck`, `npm run test:storage`, `npm run export:web`. 날짜 경계·시간대·중복 기록·취소·일정 변경·별도 동의·저장 실패·삭제 회귀 테스트를 포함한다.


## 복용 일정 기기 알림

- `expo-notifications`의 로컬 DAILY 트리거를 사용한다. 푸시 토큰을 발급하거나 서버·Expo 푸시 서비스에 제품·건강정보를 보내지 않는다.
- 내 정보에서 사용자가 `복용 알림 켜기`를 누를 때만 알림 권한을 요청한다. 복용함 기기 보관 동의와 매일 일정이 필요하며, 웹과 필요 시 복용은 알림 대상이 아니다. 알림 켜짐 설정만 기존 암호화 저장본에 추가하고 이전 데이터의 기본값은 꺼짐이다.
- 같은 HH:MM은 하나로 묶고 시간대 최대 60개를 예약한다. 잠금화면 제목·본문·식별자·데이터에 제품명·제품 코드·복용량·프로필을 넣지 않는다. 알림은 복용하라는 새 권고가 아닌 입력된 일정 확인 안내다.
- 일정 변경·제품 삭제·알림 끄기·전체 삭제 때 기존 예약을 먼저 취소한다. 취소에 실패하면 변경을 완료했다고 표시하지 않는다. 저장 성공 후 새 예약이 실패하면 저장 내용은 유지하되 알림 오류와 다시 연결 동작을 제공한다. 예약 도중 실패하면 생성한 일부 알림도 정리한다.
- 앱 시작·활성화 시 기존 예약을 확인·정리하고 현재 설정으로 다시 등록한다. 알림 권한이 해제되면 예약을 취소하고 연결 오류를 표시한다. 알림을 누르면 오늘의 복용이 있는 홈으로 이동하며 복용 완료를 자동 기록하지 않는다.
- `먹었어요` 또는 `건너뜀`을 기록해도 매일 반복 알림은 유지한다. 앱의 기기 알림 설정에서 끌 수 있다. 집중 모드·절전·OS 권한에 따라 수신이 지연될 수 있다. 시간대 변경 후에는 앱을 열어 갱신한다. Android의 정확한 알람 특별 권한은 요청하지 않는다.
