# 나를봄 제품·개발 설계

## 서비스

한국 성인의 약 검색, 복용 목록 관리, 영양소 검토 후보 안내와 질환별 건강관리를 지원한다.
진단받은 질환과 사용자가 느끼는 증상을 구분한다. 설문만으로 결핍·질환을 확정하지 않는다.

## 디자인

- 브랜드: 나를봄 / 나를 알아가고, 나에게 맞게 챙기다.
- 배경 #FFFFFF, 글자 #202124, 보조 글자 #73777E, 포인트 #176B53.
- 캐릭터와 다색 파스텔 장식을 제거한다. 여백·구분선·통일된 선 아이콘으로 정보를 정리한다.
- 홈은 검색 진입, 복용함, 건강정보 목록으로 구성한다. 큰 홍보 카드 대신 실제 행동을 먼저 보여준다.
- 색만으로 상태를 구별하지 않고 상태명·설명을 함께 제공한다.
- 미구현 기능을 실제 추천·분석 결과처럼 표현하지 않는다.

## 사용자 흐름

비회원 검색 → 정확한 제품 확인 → 복용함 추가 → 건강정보 동의·프로필 → 주의사항 확인 → 맞춤 가이드.
현재는 제품명 검색과 임시 목록까지만 구현한다. 공개 설명서의 용법과 처방받은 복용 일정을 구분한다.

## 목표 아키텍처

Expo 앱 → Node.js API → PostgreSQL.
공공 API 수집 작업이 제품·성분·주의정보를 갱신한다.
규칙 엔진이 금기·중복·용량 조건을 판정하고 AI는 근거 검색, 추가 질문과 설명을 맡는다.
현재 PostgreSQL, 수집 작업, 규칙 엔진, AI는 미구현이다.

## 예정 데이터 모델

- users / consents: 계정, 건강정보 처리 동의·철회 이력
- health_profiles / conditions / allergies: 사용자 건강 상태 및 진단·증상 구분
- products / ingredients / product_ingredients: 출처 식별자, 성분, 함량·단위
- medication_regimens / dose_logs: 실제 복용량·일정·기록
- safety_rules / evidence_sources: 적용·제외 조건, 근거, 버전·검토일
- guidance_articles / assessments: 승인된 콘텐츠, 사용한 입력·규칙·판단 한계

출처의 제품 코드로 매칭하고 이름 유사도만으로 제품을 확정하지 않는다.
함량·단위 변환, 복합제·염 형태 및 1회량/1일량을 확인한 뒤 합산한다.
상호작용 정보 미검출은 안전 판정이 아니다. 검토 후보/주의 확인/전문가 확인/정보 부족 상태를 구분한다.

## 연동 출처

- 의약품 제품 허가정보: https://data.mfds.go.kr/
- e약은요: https://www.data.go.kr/data/15075057/openapi.do
- DUR: https://www.data.go.kr/data/15059486/openapi.do
- 건강기능식품: https://www.data.go.kr/data/15056760/openapi.do
- 질환정보: https://health.kdca.go.kr/
- NIH ODS: https://ods.od.nih.gov/api/

e약은요는 전체 의약품 목록이 아니며 DUR는 모든 약·영양제 상호작용을 포괄하지 않는다.
건강기능식품 API의 실제 성분·함량 제공 범위를 검증하고 부족한 데이터는 별도 확보한다.
질환 콘텐츠는 재사용 조건, 임상 검토, 갱신 주기와 복수 질환 간 충돌을 확인한 뒤 공개한다.

## 출시 전 검증

API 키로 실응답 검증, 제품·함량 매칭, 판단 규칙의 전문가 검토, 긴급 증상 대응, 미확인 상태 처리.
건강정보 별도 동의와 수집 최소화, 서버 접근 제어, 암호화, 삭제·철회, AI 전송 범위와 보관 정책.
개인 건강정보는 일반 로그·분석 이벤트·잠금화면 알림 내용에 포함하지 않는다.
서비스 기능·문구에 따른 규제 검토 및 기기·접근성 QA를 진행한다.
