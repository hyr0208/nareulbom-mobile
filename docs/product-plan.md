# 나를봄 제품·개발 설계

## 서비스

한국 성인의 약 검색, 복용 목록 관리, 영양소 검토 후보 안내와 질환별 건강관리를 지원한다.
진단받은 질환과 사용자가 느끼는 증상을 구분한다. 설문만으로 결핍·질환을 확정하지 않는다.

## 디자인

- 브랜드: 나를봄 / 나를 알아가고, 나에게 맞게 챙기다.
- 배경 #FFFFFF, 글자 #202124, 보조 글자 #73777E, 포인트 #176B53.
- 캐릭터와 다색 파스텔 장식을 제거한다. 여백·구분선·통일된 선 아이콘으로 정보를 정리한다.
- 홈은 검색 진입, 복용함, 건강정보 목록으로 구성한다. 큰 홍보 카드 대신 실제 행동을 먼저 보여준다.
- 색만으로 상태를 구별하지 않고 상태명·설명을 함께 제공한다.
- 미구현 기능을 실제 추천·분석 결과처럼 표현하지 않는다.

## 사용자 흐름

첫 실행 선택 동의 → 5단계 건강정보 입력 또는 입력 없이 시작 → 홈 → 약 검색·복용함 관리 → 프로필 확인·수정. 이후 맞춤 가이드를 연결한다.
제품명 페이지 검색, 제품 확인 후 등록, 모바일 기기 보관 동의, 직접 입력한 복용량·매일/필요 시 일정과 전체 삭제를 구현했다. 웹은 임시 보관이다. 공개 설명서의 용법과 처방받은 복용 일정을 구분한다.

## 목표 아키텍처

Expo 앱 → Node.js API → PostgreSQL.
공공 API 수집 작업이 제품·성분·주의정보를 갱신한다.
규칙 엔진이 금기·중복·용량 조건을 판정하고 AI는 근거 검색, 추가 질문과 설명을 맡는다.
현재 PostgreSQL, 수집 작업, 규칙 엔진, AI는 미구현이다.

## 예정 데이터 모델

- users / consents: 계정, 건강정보 처리 동의·철회 이력
- health_profiles / conditions / allergies: 사용자 건강 상태 및 진단·증상 구분
- products / ingredients / product_ingredients: 출처 식별자, 성분, 함량·단위
- medication_regimens / dose_logs: 실제 복용량·일정·기록
- safety_rules / evidence_sources: 적용·제외 조건, 근거, 버전·검토일
- guidance_articles / assessments: 승인된 콘텐츠, 사용한 입력·규칙·판단 한계

출처의 제품 코드로 매칭하고 이름 유사도만으로 제품을 확정하지 않는다.
함량·단위 변환, 복합제·염 형태 및 1회량/1일량을 확인한 뒤 합산한다.
상호작용 정보 미검출은 안전 판정이 아니다. 검토 후보/주의 확인/전문가 확인/정보 부족 상태를 구분한다.

## 연동 출처

- 의약품 제품 허가정보: https://www.data.go.kr/data/15095677/openapi.do
- e약은요: https://www.data.go.kr/data/15075057/openapi.do
- DUR: https://www.data.go.kr/data/15059486/openapi.do
- 건강기능식품: https://www.data.go.kr/data/15056760/openapi.do
- 질환정보: https://health.kdca.go.kr/
- NIH ODS: https://ods.od.nih.gov/api/

e약은요는 전체 의약품 목록이 아니며 DUR는 모든 약·영양제 상호작용을 포괄하지 않는다.
건강기능식품 API의 실제 성분·함량 제공 범위를 검증하고 부족한 데이터는 별도 확보한다.
질환 콘텐츠는 재사용 조건, 임상 검토, 갱신 주기와 복수 질환 간 충돌을 확인한 뒤 공개한다.

## 출시 전 검증

API 키로 실응답 검증, 제품·함량 매칭, 판단 규칙의 전문가 검토, 긴급 증상 대응, 미확인 상태 처리.
건강정보 별도 동의와 수집 최소화, 서버 접근 제어, 암호화, 삭제·철회, AI 전송 범위와 보관 정책.
개인 건강정보는 일반 로그·분석 이벤트·잠금화면 알림 내용에 포함하지 않는다.
서비스 기능·문구에 따른 규제 검토 및 기기·접근성 QA를 진행한다.

## 현재 기기 보관

모바일은 SecureStore를 사용하고 제품 식별 정보와 복용량·일정만 보관한다. 기기 보관 동의 전에는 메모리만 사용한다.
보관 동의 철회는 전체 삭제와 함께 처리한다. 서버 계정·DB 동기화는 아직 구현하지 않는다.
저장 중단·큰 한글 데이터·손상 복원·삭제 실패를 회귀 테스트로 검증한다.

## 현재 처방약 검색·직접 등록

일반약 설명(e약은요)과 전체 의약품(허가정보)을 출처별로 검색한다. 공식 최신 08 명세의 품목 코드로 상세를 조회하며, 승인 오류는 검색 결과 없음과 구분한다.
직접 입력한 약·영양제는 별도 식별자를 부여하고 제품 정보 미확인 상태를 저장·복원한다. 제품명·함량·제조사·구분을 수정해도 복용 일정은 유지한다.
직접 등록 정보를 공식 제품과 이름만으로 연결하거나 효능·상호작용 판단에 사용하지 않는다. 추후 명시적인 제품 확인 과정을 거쳐 연결한다.
허가정보의 성분 문자열은 제공된 설명이며 정규화된 성분·함량 매핑 또는 DUR 분석을 대체하지 않는다.

## 건강정보 온보딩

건강정보 이용과 기기 보관은 각각 선택이다. 미동의 상태에서도 시작 버튼을 활성화하고 홈으로 진입한다. 문진에 동의한 경우에만 목표·기본정보·건강 상태·복용 제품·생활습관을 입력한다.
진단받은 질환과 증상을 구분하고, 항목을 건너뛴 경우에는 질환·알레르기 없음으로 바꾸지 않는다. 성별·임신·수유 입력은 선택이며 다른 선택에 따라 임의 추정하지 않는다.
프로필은 마지막 확인 이후 반영하며 건강정보 보관과 복용함 보관의 동의 범위를 분리한다. 모바일 첫 실행 안내 완료 표시는 건강정보를 제외한 상태값으로 유지한다.
건강정보 삭제는 복용함을 유지하며, 전체 삭제는 프로필·복용함·동의를 함께 지운다. 출시 전 처리방침·동의 문구와 기기별 삭제·복원·접근성 검증을 별도로 완료한다.

## 현재 홈 개인화

홈은 입력한 목표와 미입력 항목, 제품 등록·일정 기록 상태를 표시한다. 의료 판단은 하지 않고 사용자에게 다음 입력·확인 행동을 제공한다.
문진 미입력과 명시적인 없음은 구분하며, 선택한 정보를 근거로 결핍·건강점수·개인별 적합성을 계산하지 않는다. 해당 문진 단계로 바로 이동하고 저장하면 홈에 반영한다.
복용 제품은 최대 3개와 직접 기록한 일정을 보여준다. 복용 완료·알림 기능이 구현된 것처럼 표시하지 않는다. 목표별 연결은 기존 가이드와 프로필·복용함 화면이며, 질환별 콘텐츠 매칭과 추천은 다음 개발 범위다.

## 현재 가이드 연결

공식 자료 6개를 등록하고 목표·명시적으로 입력한 질환 이름으로 기기에서 연결한다. 목표·질환 연결 이유와 전체 자료 보기를 제공한다. 건강 프로필이 없을 때 개인화 결과를 만들지 않는다.
현재 질환 매핑은 고혈압·당뇨병이며 미연결 질환을 별도로 안내한다. 부분 일치·증상 추론·약 이름 기반 진단은 하지 않는다. 다른 질환·하위 유형은 자료를 개별 확인한 뒤 추가한다.
원문 갱신일과 앱 확인일을 구분하며, 원문 재사용 조건에 따라 NIH는 짧은 요약과 영문 링크, 질병관리청은 본문 복제 없이 원문 연결로 제공한다. 전문가 임상 검토 및 개인별 적합성 판단은 아직 구현하지 않았다.

## 현재 영양소 후보 안내

서비스의 첫 추천 흐름을 홈 → 식습관·기존 영양제·의료진의 검사 안내 확인 → 영양소 후보·이유·주의 확인으로 연결했다. 문진은 영양정보를 포함한 6단계다.
초기 범위는 NIH ODS의 B12·칼슘·비타민 D 자료다. 목표·피로감만으로 결핍을 추정하지 않고 조건이 확인된 후보만 표시한다. B12 강화식품 섭취 여부와 기존 성분을 확인해 답변에 따라 후보가 달라진다.
질환·복용 약 등은 검증이 필요한 상태로 분기하며 상호작용 미검출을 안전으로 표시하지 않는다. 기존 섭취, 높은 검사 결과, 정보 부족을 구분한다. 임신·수유·미성년자 등 특별한 상태에는 별도 확인을 요구한다.
추천용 정보 이용은 별도 선택 동의를 받고, 동의한 프로필 보관·삭제 체계 안에서 관리한다. 출시용 개인별 처방·용량·상품 추천 전에는 국내 기준, 약·영양제 성분 연결, 전문가 임상 검증이 필요하다.
